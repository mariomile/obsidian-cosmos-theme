# Product

## Register

product

## Users

Mario Miletta — sole user and maintainer. PM / 0-to-1 builder who lives in this
Obsidian setup daily for personal knowledge management (vault `marioverse.ai`).
Heavy power-user of tabs, Bases views, CRM notes, daily journaling — long
working sessions, mostly dark mode on macOS desktop, occasional light mode.
The "job to be done" on any given screen is reading/writing notes without
friction, so the tool should recede — except at the handful of moments
(empty states, tab bar, Bases) where a little personality earns its keep.

## Product Purpose

Cosmos is a personal "de-Baselined" fork of the Baseline Obsidian theme: it
takes Baseline's raw material and refines the rough edges into one cohesive,
Craft/Notion-inspired environment. It is not a public product with a funnel —
success is Mario opening a fresh pane and it feeling like *his* app, not a
generic theme with a snippet bolted on.

## Brand Personality

Quiet, considered, tactile. Calm focus over attention-seeking — like a
well-made physical notebook, not a dashboard trying to impress. Confidence
comes from restraint and precision (correct radii, correct shadows, correct
type scale), not from color or motion volume.

## Anti-references

- The generic Baseline/stock empty-state look this task exists to move past:
  a faint centered logo mark + two plain text action links, no personality.
- Any AI-slop tell: side-stripe accent borders, gradient text, bouncy/elastic
  easing, glassmorphism as decoration, stock "nothing here" illustrations.
- SaaS-cream / warm-neutral-by-default palettes — Cosmos's palette is
  deliberately neutral gray, tuned per-flavour (Cupertino/Fusion/Border).
- Anything that reads as "a theme on top of Obsidian" rather than "how
  Obsidian should have looked" — no visible permanent decorative chrome
  (Mario has previously rejected a permanent background behind the tab bar
  for exactly this reason).

## Design Principles

1. **Native over decorative** — every visual delta should look like it could
   ship as part of Obsidian/Baseline itself, not an obvious add-on skin.
2. **Restraint as taste** — hierarchy and geometry carry the design; color
   and motion are used sparingly and only where they earn their place.
3. **Reversible by construction** — every layer should degrade gracefully if
   disabled (a recurring pattern in this repo: "togli lo snippet e torni a
   Baseline puro").
4. **One surface, not a patchwork** — tabs, sidebar, Bases, empty states
   should read as one designed environment, not disconnected patches.
5. **Approved before it ships** — visual directions get an explicit sign-off
   from Mario before landing (this repo's own session history is full of
   "direzione approvata" / "bocciato" decisions); this file records intent,
   not a substitute for that review.

## Accessibility & Inclusion

Single-user personal tool, no formal WCAG target. Still: respect
`prefers-reduced-motion`, keep text contrast legible even within a muted-gray
palette (the palette must stay readable, not just quiet), and never let a
"considered" visual choice become a "hard to read" one.
